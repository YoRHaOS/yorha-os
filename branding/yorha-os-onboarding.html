Joining YoRHa OS

Get in · Set up · Don't overwrite anyone

What this covers

Three things, in order.

  1. Getting into the GitHub organisation.
  2. Putting the project onto your own Arch machine.
  3. Working alongside other people without wiping their work.

Take it slowly. Every step is one command or one click. Nothing here can break anything permanently.

Part one · Access

You get invited to the organisation.

The project lives at github.com/YoRHaOS/yorha-os — owned by an organisation, not by one person. An Owner sends you an invite.

  1. Check your email, or your GitHub notifications.
  2. Click Accept invitation.
  3. That's it. You're in the org.
Part one · Access

What that lets you do.

You can

  • Push your own branches
  • Open pull requests
  • Review other people's work

You can't

  • Force-push over main
  • Change repository settings

That second list is deliberate. It's the safety net that makes the rest of this video true — not a lack of trust.

Part two · Setup

Copy the project down.

One command. It pulls the entire project — every file, and every change anyone has ever made to it — onto your machine.

$ git clone https://github.com/YoRHaOS/yorha-os.git ~/yorha-os

This copy is yours. Editing it does nothing to anyone else until you deliberately send changes back.

Part two · Setup

Read this before you expect an installer.

YoRHa OS is not a downloadable distro yet. There is no ISO. Right now the project is a set of configuration files you apply on top of an Arch Linux install you already have.

The house has to exist before you can decorate it. Arch is the house. This repo is the decoration.

Part two · Setup · Step one

Start from working Arch.

  • Arch Linux installed and booting
  • A user account you can log into
  • sudo working
  • Internet connected

If any of those four aren't true, stop here and fix that first. Everything below assumes all four.

Part two · Setup · Step two

Install the programs the project needs.

The repo carries a shopping list of every package. Feed the list to pacman and it installs all of them.

$ sudo pacman -S --needed - < base/packages/explicit.txt

Run this from inside the folder you cloned. --needed means it skips anything you already have.

Part two · Setup · Step three

Put the configuration in place.

This is the step that actually makes the desktop look and behave like YoRHa OS — the keybinds, the layout, all of it.

$ cp profiles/hyprland/hyprland.conf ~/.config/hypr/hyprland.conf

Building a Plasma or GNOME profile instead? Then you're creating profiles/plasma/, not copying this one. Same shape, your folder.

Part two · Setup

One honest gap.

Those last two steps are done by hand. There is no install.sh that runs them for you yet.

Which makes writing it an excellent first contribution — a small script that installs the packages and copies the configs, so nobody ever types this by hand again.

Part three · Working together

There is one rule.
Never commit straight to main.

mainThe real one · protected
◄──
your-branchYour scratch space
Part three · The loop

Four steps. Every single time.

  1. git pull on main — start from the newest version, not last week's.
  2. git checkout -b yourname/what-youre-doing — your own space to work in.
  3. git commit then git push — save your work, send it up.
  4. Open a pull request — someone looks at it before it lands.

Same loop that was used to add the Hyprland config. Nothing new to learn — just repeat it.

Part three · Why it's safe

You cannot quietly wipe each other's work.

  • You mostly edit different folders — one person in profiles/hyprland/, another in profiles/plasma/.
  • Nothing reaches main without a pull request you can see first.
  • If two people do edit the same lines, git stops and asks a human. It never silently picks a winner.
  • Every change is kept forever. Anything wrong can be undone.
Part three · The one gap

Shared files need a word first.

Some files don't belong to any one person — the package list, base/packages/explicit.txt, and the top-level documents.

Before you touch one, say so. A single message is enough. Everything else the system handles for you.

If you remember nothing else
  1. Accept the org invite.
  2. Clone the repo onto working Arch.
  3. Install the package list, copy the config in.
  4. Branch → commit → push → pull request. Never main.
  5. Speak up before editing shared files.
